SYMPTOM: prisma.learnedVocabulary.upsert({ where: { userId_bundleId_term: { userId, bundleId: null, term } } }) throws 'Argument bundleId must not be null'
CAUSE: Prisma composite unique constraints don't accept null in where clauses for both findUnique and upsert — affects ALL global vocabulary (no bundleId)
FIX: Replace upsert with manual findFirst + create/update pattern:
```typescript
const existing = await prisma.learnedVocabulary.findFirst({
  where: { userId, bundleId: bundleId || null, term },
  select: { id: true, rawVariants: true },
});
if (existing) {
  await prisma.learnedVocabulary.update({
    where: { id: existing.id },
    data: { occurrences: { increment: 1 } },
  });
} else {
  await prisma.learnedVocabulary.create({
    data: { userId, bundleId: bundleId || null, term, ... },
  });
}
```
PREVENT: Never use upsert or findUnique with composite unique constraints that contain nullable fields — always use findFirst by id then update/create

PATTERN: Enum guard on DB read
WHAT: parseSettings() validates audio_quality_preset against VALID_AUDIO_QUALITY_PRESETS = new Set(Object.values(AudioQualityPreset)) before accepting from DB.
WHERE: api/src/utils/settingsCache.ts
WHY: Old DB records may have stale enum values ('high', 'ultra', 'balanced') from before the schema was locked down. Without validation, these would pass through, then fail Zod strict mode validation on the next POST, causing mysterious 400 errors for affected users.
FIX PATTERN: const VALID = new Set(Object.values(SomeEnum)); return VALID.has(raw) ? raw : defaultValue;
APPLIES TO: Any enum field read from DB after a schema change that removes valid options

SYMPTOM: GET /sync/settings returns 401 at T=2.3s after fresh OAuth exchange. Works fine after app restart ~80s later. /devices/register succeeds at same T=2.3s.

CAUSE: The 401 is generated by the Rust desktop app's HTTP layer, not the Express API. Server logs confirm zero 401s for /sync/settings across both API pods for their entire lifetime. The request at 09:00:39 never reached Express — the OTC exchange at 09:00:37 is logged, then a full gap until 09:01:45 (post-restart).

KEY EVIDENCE:
- Both API pods: 0 total 401s for /sync/settings ever
- ForwardAuth middleware removed Nov 2025, not the cause
- /devices/register at same timestamp was a LOCAL CACHE HIT — never hit the server
- The 77ms client-observed response time (39.314→39.391) is consistent with a local check

FIX: Inspect Rust HTTP client for an auth interceptor or pre-flight token validator that checks token state before sending. The token state after OAuth callback may not be propagated synchronously within the app at T=2.3s.

PREVENT: Token state update after OAuth exchange should be synchronous/awaited before triggerAutoSync fires at T+2000ms.

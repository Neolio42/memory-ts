SYMPTOM: `prisma migrate dev` fails with migration drift (previously modified migrations)
CAUSE: Dev DB schema diverged from migration history
FIX: Apply SQL directly then record in _prisma_migrations:
```javascript
// 1. Apply the SQL
await p.$executeRawUnsafe(fs.readFileSync('./migration.sql', 'utf8'));
// 2. Record in prisma migrations table
await p.$executeRawUnsafe(`
  INSERT INTO _prisma_migrations (id, checksum, migration_name, logs, started_at, finished_at, applied_steps_count)
  VALUES (gen_random_uuid(), $1, '20260223_add_style_attributes', NULL, NOW(), NOW(), 1)
  ON CONFLICT DO NOTHING
`, checksum);
```
PREVENT: Use `prisma migrate deploy` (not `dev`) in CI/CD — deploy never resets. Run `prisma migrate status` to verify before deploying.
GOTCHA: After manual fix, run `npx prisma db push --accept-data-loss` or verify with `prisma migrate status` shows 'Database schema is up to date!'

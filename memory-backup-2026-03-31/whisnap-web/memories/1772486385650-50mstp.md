WHAT: Two desktop app update endpoints existed simultaneously — the real one and a dead duplicate

REAL ENDPOINT (used by Tauri):
  GET /releases/update/{target}-{arch}/{current_version}?channel={channel}
  File: api/src/routes/releases.ts
  Platform format: full arch-specific (e.g., darwin-aarch64, windows-x86_64)
  Response: Tauri-native format { version, platforms: {...} }
  No update: 204 No Content
  Configured in: tauri.conf.json → staging.api.whisnap.com/releases/update/...

DEAD DUPLICATE (removed):
  GET /desktop/update/:platform/:currentVersion
  File: api/src/routes/desktop.ts
  Platform format: bare OS name (darwin, windows) — never matched full arch names
  Response: custom wrapper { success, data: { updateAvailable } }
  Status: never called by anything, broken by design

FIX: Removed dead endpoint + unused releaseService import from desktop.ts
COMMIT: 3a0a813

GOTCHA: The /releases/download/:platform endpoint legitimately accepts bare platform names (darwin) for downloads — partial matching in getDownloadUrl/getLatestRelease is intentional. Only getUpdate was wrong, and it was in the dead code anyway.

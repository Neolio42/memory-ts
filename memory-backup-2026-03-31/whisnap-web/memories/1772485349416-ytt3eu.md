WHAT: WebSocket start_transcription payload needs two new optional fields to activate style/vocab learning.

WHERE: WebSocket start_transcription message + HTTP POST /transcribe multipart form.

HOW:
```json
{
  "type": "start_transcription",
  "bundleId": "com.apple.mail",
  "appContext": {
    "windowTitle": "Re: Q3 Budget - Mail",
    "inputFieldContent": "",
    "threadContext": "Previous: Can you review?",
    "fileLanguage": null,
    "cursorContext": null
  }
}
```

Source: `NSWorkspace.shared.frontmostApplication?.bundleIdentifier`

Field limits: bundleId=256, windowTitle=500, inputFieldContent=2000, threadContext=2000, fileLanguage=50, cursorContext=500.

WHY: bundleId is the key that unlocks per-app formatting, vocab learning per app, and style fingerprinting. Without it, system behaves exactly like before this commit (no regression).

PHASES:
- Phase 1 (one line): bundleId only
- Phase 2 (easy): + windowTitle
- Phase 3 (AX): + threadContext, inputFieldContent
- Phase 4 (editors): + fileLanguage, cursorContext

GOTCHA: /transcribe route is served by transcription-sync.ts — the filename 'sync' means synchronous (not a separate sync endpoint). Both WebSocket and HTTP paths accept these fields.

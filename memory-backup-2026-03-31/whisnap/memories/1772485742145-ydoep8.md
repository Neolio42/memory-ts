TECHNICAL: Async-safe AX capture pattern

WHAT: Both capture sites (live recording ~line 763, command recording ~line 1304 in transcription/service.rs) use:
```rust
let (bundle_id, app_context) = tokio::time::timeout(
    std::time::Duration::from_millis(500),
    tokio::task::spawn_blocking(|| {
        let sys_service = SystemIntegrationService::new_for_detection();
        sys_service.capture_frontmost_app_context()
    })
).await
    .ok()
    .and_then(|r| r.map_err(|e| {
        warn!(target: "system::integration", error = %e, "App context capture failed");
        e
    }).ok())
    .unwrap_or((None, None));
```

WHY: AX calls are synchronous FFI — a frozen app or screen sharing can block indefinitely. Running on Tokio executor thread would stall all async work.

GOTCHA: Without timeout + warn, panics inside spawn_blocking are silently swallowed as `Err(JoinError)` and `.unwrap_or((None, None))` returns None with no log. Always map the Err to a warn before unwrap_or.

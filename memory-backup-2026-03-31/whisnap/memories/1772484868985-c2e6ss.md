PATTERN: 5-state machine in service.rs FnShortcutCoordinator

COMPONENTS:
- Idle: no active recording, FN not held
- FnHeld { since, shortcut_fired, was_toggle_active }: FN is down, ≥300ms timer pending
- PushToTalkActive: recording via PTT (hold-to-record; release stops it)
- ToggleRecordingActive: recording via toggle (releasing FN does NOT stop it)
- CommandModeActive: cloud command mode active

KEY TRANSITIONS:
- Idle → FnHeld: bare FN pressed AND (PTT or toggle mapped to "FN")
- FnHeld → Idle: FN released in <300ms (language switch safe zone)
- FnHeld → PushToTalkActive: timer fires ≥300ms AND bare FN = PTT AND was_toggle_active=false
- FnHeld → ToggleRecordingActive: timer fires ≥300ms AND bare FN = toggle AND was_toggle_active=false
- FnHeld → Idle: timer fires ≥300ms AND bare FN = toggle AND was_toggle_active=true (stop recording)
- ToggleRecordingActive → FnHeld(was_toggle_active:true): FN pressed again
- Any active state + Escape → cancel → Idle
- FN+key down (PTT keybind) → instant PushToTalkActive from Idle
- FN+key up (PTT keybind) → Idle from PushToTalkActive

WHY: Separating PushToTalkActive from ToggleRecordingActive is necessary because FN release means 'stop' for PTT but 'continue' for toggle.

WHAT: The npm debug script RUST_LOG filter for FluidAudio development

CURRENT (fixed) RUST_LOG in package.json:
```
RUST_LOG=inference::fluidaudio=trace,inference::parakeet=trace,transcription=debug,orchestrator=debug,model::loading=debug,model::resolution=debug
```

WHY transcription=debug matters: DynamicTranscriber routing logs ('Routing to FluidAudio transcriber') are under the transcription target. Without this, zero FluidAudio logs appear even if transcription runs.

WHY orchestrator=debug matters: The orchestrator logs 'Starting transcription execution' — without this, you can't tell if the pipeline reached the transcriber at all.

GOTCHA: If you see 'Preferred model is available' but no 'Routing to FluidAudio transcriber', the issue is log visibility OR the recording pipeline isn't calling the transcriber (check orchestrator target first).

SYMPTOM: Production app builds from GitHub Actions had updater pointing at staging.api.whisnap.com instead of api.whisnap.com. All shipped apps (<=1.0.5) check staging for updates.

CAUSE: build-and-sign-local.sh had a sed patch swapping staging->prod domain before build, but release.yml (GitHub Actions) never included this step.

FIX: Added sed step to release.yml in the 'Update version' step:
  sed -i 's|staging.api.whisnap.com|api.whisnap.com|g' src-tauri/tauri.conf.json
This runs before tauri build so the prod domain gets baked into the binary.

PREVENT: tauri.conf.json always lives as staging in git. The local prod script (build-and-sign-local.sh) patches+restores it. CI must also patch it (no need to restore on CI - disposable checkout).

WORKAROUND (until 1.0.6): Keep staging.api.whisnap.com serving the same latest version as prod. Existing apps will still update correctly via staging endpoint.

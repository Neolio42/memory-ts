TECHNICAL:
  WHAT: When a Rust timeout fires before the Swift FFI callback, the Rust side must NOT reclaim the userdata box. The Swift callback will eventually fire and must safely handle the abandoned context.
  WHERE: src-tauri/src/features/inference/backends/fluidaudio_ffi.rs — load_model and transcribe timeout paths
  HOW:
    // WRONG (use-after-free):
    let _context = unsafe { Box::from_raw(context_ptr) }; // drop it
    
    // CORRECT (intentional leak, Swift handles cleanup):
    consumed_flag.store(true, Ordering::SeqCst);
    // The Swift callback will eventually fire. It checks consumed_flag —
    // if true, it calls mem::forget on the Box instead of using the sender.
    return Err(anyhow!("timed out"));
  WHY: Swift async is not cooperative with Rust cancellation. The Swift callback WILL fire eventually even after Rust timeout. If Rust freed the memory, Swift would dereference freed memory (use-after-free/UAF).
  GOTCHA: This applies to ALL C FFI patterns where Swift callbacks are involved. When in doubt: leak, don't free. Leaking a few KB per timeout is safe; UAF causes crashes.

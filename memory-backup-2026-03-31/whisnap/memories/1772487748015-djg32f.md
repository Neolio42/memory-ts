PATTERN: Swift accelerated features are compiled as Swift packages with @_cdecl exports, linked statically into the Tauri binary at build time.

EXISTING EXAMPLES:
- FoundationModelsWrapper — Apple Intelligence text completions via @_cdecl C exports
- FnKeyHelper — macOS fn key handling

HOW IT WORKS:
1. Swift package lives in src-tauri/swift/ or similar
2. build.rs compiles the Swift package and links via swift_rs or manual rustc-link directives
3. Swift functions exported with @_cdecl("function_name") → called from Rust via extern "C"
4. Callbacks use unsafe fn pointers for async results

FOR FLUIDAUDIO:
- Create Swift package: FluidAudioWrapper
- Export: transcribe_fluid_audio(audio: UnsafePointer<Float>, len: Int32, model_path: UnsafePointer<CChar>, callback: @escaping (UnsafePointer<CChar>?) -> Void)
- Rust FFI bridge: src-tauri/src/features/inference/backends/fluid_audio_ffi.rs
- Feature gate: #[cfg(all(feature = "fluidaudio", target_os = "macos"))]

NOT a sidecar/XPC — static linking means same process, no IPC overhead.

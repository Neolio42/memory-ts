TECHNICAL: delete_model command handler checks if the target model is currently active before delegating to ModelFileService.

WHERE: src-tauri/src/commands/models.rs — delete_model command handler

HOW:
```rust
pub async fn delete_model<R: Runtime>(model_id: String, app: AppHandle<R>) -> Result<(), String> {
    let settings_service = app.state::<Arc<crate::features::settings::service::SettingsService<R>>>();
    let settings = settings_service.load_settings();
    if let Some(ref active_id) = settings.model.model_id {
        if active_id == &model_id {
            return Err("Cannot delete the currently active model. Switch to a different model first.".to_string());
        }
    }
    let model_service = app.state::<Arc<ModelFileService<R>>>();
    model_service.delete_model(&model_id).await.map_err(|e| { ... })
}
```

WHY: ModelFileService doesn't hold a reference to SettingsService, so the check lives at the command boundary which has AppHandle access.

GOTCHA: There's a TOCTOU race — settings are checked then awaited before deletion. If the model becomes active between check and delete, it can still be deleted. A future fix would require atomic settings+deletion transaction.

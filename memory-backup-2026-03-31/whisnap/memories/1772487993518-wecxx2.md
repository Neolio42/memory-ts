TECHNICAL:
  WHAT: FluidAudio CoreML integration achieves dramatically faster transcription than sherpa-rs ONNX CPU
  HOW: Backend routing confirmed via logs:
    'Resolved backend for active model, model_id=parakeet-tdt-0.6b-v3-coreml, backend_id=fluidaudio'
    'Routing to FluidAudio transcriber'
    'FluidAudio transcription completed, text_length=88' (10.7s audio in 134ms)
  WHY: CoreML on Apple Silicon Neural Engine vs ONNX CPU inference
  PERFORMANCE BENCHMARKS:
    - 10.7s audio → 134ms transcription (80x RTF)
    - 19.2s audio → 200ms transcription (96x RTF)
    - 3.4s audio → 161ms transcription (21x RTF — overhead-dominated for short clips)
  GOTCHA: The 'Loading FluidAudio CoreML model' log appears on every transcription call because load_model is called each time. With the OnceLock cache fix, this no longer triggers a real FFI call after the first load — it returns immediately from cache.

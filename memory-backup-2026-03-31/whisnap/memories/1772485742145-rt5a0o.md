ARCHITECTURE: App Context Capture Edge Case Handling

PATTERN: Layered filtering before capturing input_field_content:
1. Terminal apps → skip input entirely (iTunes `is_terminal_app()` check)
2. AXWebArea role → NOT in TEXT_INPUT_ROLES (returns entire page DOM)
3. AXSecureTextField role → skip (password/API key fields)
4. `AXNumberOfCharacters` (CF length check, no allocation) → if > max_chars*4 units, still read but tail-truncate
5. Tail truncation: if char_count > 5000, skip = char_count - 5000, take last 5000 chars
6. Strip: control chars (keep \n, \t), BOM (\u{FEFF}), ZWSP (\u{200B}), line/paragraph separators (\u{2028}, \u{2029})

COMPONENTS:
- `TEXT_INPUT_ROLES`: ["AXTextField", "AXTextArea", "AXComboBox", "AXSearchField"] — actual input fields only
- `is_terminal_app(bundle_id)` called before AX session
- `CFStringGetLength` checked before `AXValue` allocation
- Tail logic: `cleaned.chars().skip(char_count - max_chars).collect()`

WHY tail not head: Cursor is at the end — the last N chars is where active editing happens (chat compose, email draft, code near cursor). A 500-line code file's last 5000 chars is the context that matters.

WHY AXWebArea removed: Returns entire visible page DOM — megabytes of text, not a user input field. Browsers and Electron apps (Slack, VS Code, Discord) all use AXWebArea for content areas.

REJECTED: Blacklisting editor bundle IDs — too fragile, removes functionality. AXNumberOfCharacters threshold + tail truncation is the correct generic solution.

SYMPTOM: After every Parakeet transcription, logs showed:
  'Dropping context, model_id=parakeet-tdt-0.6b-v2-int8'
  'Recognizer dropped'
  'Context cleanup completed'
This made it look like the model was being freed each time (it wasn't — the underlying ZipFormer was shared via Arc).

CAUSE:
1. get_or_load_parakeet_context() returns Arc::new(parakeet_ctx.clone()) on cache hit — deep-clones the struct, shares Arc<RwLock<ZipFormer>> inside
2. parakeet_transcriber.rs held this clone for the whole transcribe() call, then dropped it at end of scope
3. Drop impl had: acquire write lock on recognizer → immediately drop guard → log 'Recognizer dropped' — fired for EVERY clone drop, not just actual deallocation

FIX #1 (parakeet_transcriber.rs): Immediately drop() the clone returned by get_or_load_parakeet_context before transcription starts — we only need to ensure the model is cached, not hold the clone:
  let _ensure_loaded = self.inference_manager.get_or_load_parakeet_context(...);
  drop(_ensure_loaded);  // ← added
  // transcribe_with_parakeet fetches from cache independently

FIX #2 (parakeet.rs Drop impl): Only log/lock when Arc::strong_count == 1 (actual deallocation). Removed the write-lock-then-drop-guard pattern that fired on every clone drop.

PREVENT: Any InferenceContext Drop impl should check strong_count before doing expensive work.

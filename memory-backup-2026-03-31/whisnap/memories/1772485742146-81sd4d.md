ARCHITECTURE: Full bundleId + appContext Pipeline

PATTERN: Data flows from system capture through the transcription strategy to both transport layers.

COMPONENTS:
1. `service.rs` (system_integration): `capture_app_context_macos(bundle_id: Option<&str>)` → returns `(Option<String>, Option<AppContext>)` where AppContext has window_title, input_field_content, cursor_context, app_name, bundle_id
2. `context_builder.rs`: `with_app_info(bundle_id, app_context)` setter → stored in `ExecutionContext`
3. `cloud_stream_strategy.rs`: All 3 `CloudTranscribeOptions` construction sites pass `bundle_id` and `app_context` from context
4. `websocket_client.rs`: `StartTranscriptionConfig` forwards bundle_id + app_context to WebSocket handshake
5. `api_client.rs`: HTTP multipart adds `bundleId` as text field + `appContext` as JSON string

WHY: Cloud API needs app context for per-app LLM formatting adaptation (tone, dictation style, vocabulary).

SERIALIZATION: `AppContext` uses `#[serde(rename_all = "camelCase")]` + `skip_serializing_if = "Option::is_none"` on all 5 fields — only present fields are sent.

DEV COMMAND: `npm run tauri:context` → `RUST_LOG=off,system::integration=debug,transcription=info tauri dev`

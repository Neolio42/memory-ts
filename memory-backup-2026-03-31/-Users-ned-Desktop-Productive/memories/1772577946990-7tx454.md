WORKFLOW: Memory curation procedure for @rlabs-inc/memory

PATTERN:
1. Glob project memories + global memories to map existing IDs
2. Read primer + sample existing memories to understand current state
3. For each new memory: find semantic duplicates/supersessions in existing memories
4. Execute supersessions: set status→superseded + superseded_by on OLD memory; set supersedes on NEW memory
5. Add bidirectional related_to links between semantically related memories
6. Evaluate action_required memories: clear if the action was completed this session
7. Verify personal primer against new personal memories; update only if genuinely new content

KEY FILE FIELDS TO EDIT:
- status: 'active' | 'superseded'
- superseded_by: [id]
- supersedes: [id]
- related_to: [id1, id2] (always bidirectional - update both files)
- action_required: true | false

GOTCHA: Must re-read file before each Edit call - the tool requires prior read in conversation
GOTCHA: Edit old_string must be unique; provide enough surrounding context to disambiguate
GOTCHA: Glob returns files sorted by mtime - newer memories have larger numeric IDs

WHEN TO UPDATE PRIMER: Only when new personal memories contain facts genuinely absent from primer. Primer tends to already contain the synthesis; recordings/session memories add detail not primer-worthy.

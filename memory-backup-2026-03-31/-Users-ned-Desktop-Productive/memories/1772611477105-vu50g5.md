SYMPTOM: Running 'memory ingest --session <id>' from within a Claude Code session fails silently or with nested session detection error.
CAUSE: @rlabs-inc/memory detects it's already running inside a Claude Code session and blocks nested invocation to prevent recursive memory ingestion.
FIX: Always run memory ingest commands from a separate terminal window, not from within Claude Code.
ALSO APPLIES TO: Any memory CLI commands that trigger new Claude sessions internally.
GOTCHA: This is why session 47ac9782 is still pending - it was queued from inside Claude Code and couldn't execute.
COMMAND PATTERN:
  # Wrong: run from Claude Code terminal
  # Right: open new Terminal.app/iTerm window, then:
  memory ingest --session <session-id>

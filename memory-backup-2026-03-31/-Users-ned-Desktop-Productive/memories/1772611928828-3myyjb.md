PATTERN: When processing debug memories about the same bug across multiple sessions:
  - Identify the supersession chain (oldest → newest iteration of the same diagnosis)
  - Mark older ones status=superseded, set superseded_by pointing to canonical
  - Update canonical with supersedes field listing what it replaced
  - Stale action_required=true on status=superseded memories is a known recurring pattern — always audit and clear

EXAMPLE FROM THIS SESSION:
  p50d36 (session f953d4e1) → 8wxttw (prior session) → pfm4uk (session 03bcaa53, canonical)
  Both p50d36 and 8wxttw were set to status=superseded, superseded_by=pfm4uk, action_required=false
  pfm4uk.supersedes = [8wxttw]

WHEN TO SUPERSEDE vs LINK:
  - Supersede: same bug/issue, newer memory has more complete diagnosis or supersedes earlier understanding
  - Link (related_to): complementary angle on same domain, both remain valid

GOTCHA: Some superseded memories may not have superseded_by set — check for status=superseded without superseded_by and patch it.

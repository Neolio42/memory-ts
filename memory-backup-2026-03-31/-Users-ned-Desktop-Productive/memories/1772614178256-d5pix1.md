PATTERN: When processing a memory curation batch:
1. Glob all existing memories → read new ones + action_required ones + topic-overlapping existing ones
2. Map supersessions: newer memory on same topic supersedes older → set status=superseded + superseded_by on old, supersedes + related_to on new
3. Clear stale action_required: if a superseded memory still has action_required=true, clear it (new memory carries the action forward)
4. Link bidirectionally: related memories should reference each other in related_to arrays
5. Check primer: if personal memories add new facts not in primer, update it. If primer is already current, skip.
WHEN: Every curation management session
WHY: Superseded memories with action_required=true still surface as noisy alerts. Bidirectional links enable co-retrieval. Primer must reflect current state not historical snapshot.
GOTCHA: Never update primer just to refresh wording - only update when new substantive facts emerge.

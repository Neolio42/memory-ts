PATTERN: When running memory management on a batch of new memories:
  1. Glob all existing project + global memories
  2. Read primer and grep for domain/tag overlaps before writing anything
  3. Read all action_required memories — they have pending blockers that new memories may resolve or relate to
  4. Read new memories and identify relationship candidates
  5. Fix factual errors discovered during cross-reading BEFORE adding relationship links
  6. Add bidirectional related_to links in parallel batches
  7. Update primer last

WHEN: Any curation session with 5+ new memories, or when new memories touch personal/identity content.

WHY: Relationship links discovered during read phase inform primer updates. Factual errors in older memories get caught when cross-referencing new content (e.g., Dec 2024 vs Dec 2025 caught by comparing xc61el against new 4pqyz9).

GOTCHA: Edit tool requires reading a file before editing it in the same session. Pre-read all files you intend to edit, or re-read immediately before editing. Cannot batch edit without intervening reads.

ADDITIONAL GOTCHA: Stale action_required=true flags on status=superseded memories are a recurring pattern — always audit action_required memories and clear the flag if the memory is already superseded.

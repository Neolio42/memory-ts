WHAT: SF Symbol image caching to reduce per-button allocation overhead in keyboard extension
WHERE: WhisnapKeyboard/KeyboardView.swift
HOW:
```swift
private enum KeyImages {
    private static let specialConfig = UIImage.SymbolConfiguration(pointSize: 18, weight: .regular)
    static let shift      = UIImage(systemName: "shift",        withConfiguration: specialConfig)
    static let shiftFill  = UIImage(systemName: "shift.fill",   withConfiguration: specialConfig)
    static let capslockFill = UIImage(systemName: "capslock.fill", withConfiguration: specialConfig)
    static let deleteLeft = UIImage(systemName: "delete.left",  withConfiguration: specialConfig)
    static let globe      = UIImage(systemName: "globe",        withConfiguration: specialConfig)
}
// Usage: button.setImage(KeyImages.shift, for: .normal)
```
ALSO:
- Set shadowPath in layoutSubviews (not didLayoutSubviews) — avoids per-frame offscreen render
- Remove shouldRasterize — with shadowPath set, rasterization is wasteful not helpful
- Lazy var hapticGenerator — UIImpactFeedbackGenerator.prepare() talks to system services, only init on first key tap

WHY: rebuildLayout() creates 30+ buttons. Each UIImage(systemName:) allocates a new image object. In keyboard extensions with ~50MB limit, this matters. Static let means one allocation total.

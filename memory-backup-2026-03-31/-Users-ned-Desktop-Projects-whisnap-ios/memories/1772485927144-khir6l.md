ARCHITECTURE
PATTERN: Two-process audio pipeline via shared filesystem
COMPONENTS:
1. AudioCaptureService: captures mic audio, fires onAudioBuffer callback with [Int16] PCM data
2. RelayService: receives PCM from callback, writes chunk_NNNNNN.pcm files to App Group directory, updates relayChunkCount in UserDefaults(suiteName: 'group.com.whisnap.app')
3. KeyboardTranscriptionService: polls relayChunkCount every 0.15s, reads new chunks from lastReadChunkIndex+1 to currentCount, base64-encodes and sends as 'audio_data' WebSocket messages
4. WebSocket server: receives audio, returns transcript
KEY PATHS:
- App Group dir: FileManager.default.containerURL(forSecurityApplicationGroupIdentifier: 'group.com.whisnap.app')
- Chunk files: chunk_000001.pcm format (6-digit zero-padded)
- UserDefaults keys: RelayKeys.relayActive, RelayKeys.relayChunkCount, RelayKeys.relayExpiry
WHY: Keyboard extensions can't use audio capture directly (need Full Access + complex permissions). Main app captures and shares via files.
REJECTED: Direct IPC — too complex; XPC — not available for keyboard extensions

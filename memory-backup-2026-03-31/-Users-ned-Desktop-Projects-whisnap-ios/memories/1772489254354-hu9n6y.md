QUESTION: Should Settings.swift singleton be rewritten from scratch?

CONTEXT:
1. Singleton init (lines 131-152): NSLock taken, then Task { await ... } launched inside lock scope — Task won't run until lock is released, but init might return before Task completes, meaning consumers read default values briefly.
2. Two reload() overloads (lines 206-215): One takes Settings parameter, one has no params — completely different behavior, deeply confusing.
3. static func clear() uses `await` on a property setter (line 221) — not valid Swift syntax, likely doesn't compile or does something unexpected.
4. Debounce save uses nested unstructured Tasks unnecessarily.

BLOCKERS: Existing code works well enough to not block other features — it's load (now fixed via direct UserDefaults read) that was the critical path.

OPTIONS: 
- Rewrite as @MainActor class with straightforward async init
- Keep as-is but fix the three specific bugs above

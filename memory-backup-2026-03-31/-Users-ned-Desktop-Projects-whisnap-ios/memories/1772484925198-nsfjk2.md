SYMPTOM: If keyboard is dismissed while audio is being processed (state = .processing), the stopCompletion callback fires and calls textDocumentProxy.insertText() on a deallocated proxy.

CAUSE: viewWillDisappear only cancelled recording for state == .recording, missing the .processing state.

FIX:
```swift
override func viewWillDisappear(_ animated: Bool) {
    super.viewWillDisappear(animated)
    // Cancel if busy — covers both .recording AND .processing states
    if state.isBusy {
        cancelRecording()
        revertToKeyboard()
    }
}
```

WHERE: KeyboardViewController.viewWillDisappear

PREVENT: Whenever checking 'is something happening' in keyboard lifecycle, prefer a computed `isBusy` property that covers all active states rather than checking individual cases.

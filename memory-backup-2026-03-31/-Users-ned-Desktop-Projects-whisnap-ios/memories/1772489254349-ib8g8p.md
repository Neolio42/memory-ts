SYMPTOM: App shows 401s on launch even when not signed in. Auth error alert appears, user taps 'Sign In', alert immediately reappears. Button appears unresponsive.

CAUSE: Dead refresh tokens in keychain → refreshIfNeeded() called → refresh fails → authError set → alert shown → user dismisses → hasCredentials still true (tokens still in keychain) → refreshIfNeeded() called again → infinite loop.

FIX (all 4 parts needed):
```swift
// 1. Clear dead tokens on failure
private func handleRefreshFailure() async {
    try? KeychainManager.clearAll()
    isAuthenticated = false
    if wasAuthenticatedThisSession {
        authError = .notAuthenticated  // Only alert if was actually logged in
    }
}

// 2. Track if user ever actually authenticated this session
private var wasAuthenticatedThisSession = false
// Set to true only when refresh succeeds or magic link completes

// 3. Guard concurrent refreshes
private var isRefreshing = false
guard !isRefreshing else { return }

// 4. Skip launch-time foreground notification
NotificationCenter.default.publisher(for: UIApplication.didBecomeActiveNotification)
    .dropFirst()  // checkAuthenticationStatus() handles launch
    .sink { ... }
```

PREVENT: Any time a refresh fails, always clear the dead credentials. Don't surface auth errors to users on cold launch with stale tokens — silently clean up instead.

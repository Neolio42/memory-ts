PATTERN: Always-on mic relay workaround for keyboard extension mic restriction

COMPONENTS:
  1. User taps mic in keyboard → keyboard checks UserDefaults(suiteName: appGroupId).bool(forKey: 'relayActive')
  2. No relay → keyboard deeplinks to whisnap-ios://relay → main app opens RelayView
  3. RelayService (main app):
     - Starts AVAudioEngine at 16kHz mono PCM
     - Writes numbered files: chunk_000001.pcm, chunk_000002.pcm... to App Group container
     - Updates UserDefaults: relayActive=true, relayExpiry=timestamp, relayChunkCount=N
     - Shows 'Switch back to your app' UI with countdown timer
  4. User switches back to their app, taps mic again → relay active → keyboard starts KeyboardTranscriptionService
  5. KeyboardTranscriptionService:
     - Opens WebSocket to wss://staging.api.whisnap.com/ws
     - Authenticates with JWT from shared Keychain (AccessGroup: group.com.whisnap.ios)
     - Polls App Group directory every 150ms for new PCM chunks
     - Streams base64-encoded audio chunks over WebSocket
     - Receives partial_transcript messages (wrapped in 'data' object)
     - Displays partials in keyboard overlay
     - On stop: sends finalize → gets final transcript → textDocumentProxy.insertText()

WHAT MAIN APP DOES WHEN RELAY ACTIVE: Nothing automatic. If main app record button pressed, CloudTranscriptionService hooks into relayService.onAudioChunk instead of its own mic.

CRITICAL: Token must be valid before connecting — check KeychainManager.isTokenExpired() first

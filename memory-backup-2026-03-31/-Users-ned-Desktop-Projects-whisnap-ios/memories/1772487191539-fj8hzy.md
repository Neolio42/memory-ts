DECISION: User clarified the intended UX for the main app recording:

MODE 1 - Standalone (no Relay):
- User taps record button in main app WITHOUT Relay active
- Uses AudioCaptureService directly (not RelayService)
- Gets transcript back, can copy/share
- This is the traditional dictation experience

MODE 2 - Relay-connected:
- User has Relay toggle ON → Relay session starts
- User taps record button in main app WITH Relay active
- Uses RelayService as audio source (Relay already running)
- Same visual experience (record button, transcript below)

RELAY TOGGLE:
- Separate toggle in the app to start/stop the Relay
- When toggle is ON: mic stays active in background for keyboard use
- When toggle is OFF: standard standalone recording mode
- Toggle location: TBD (plan written, pending implementation)

IMPLICATION FOR CloudTranscriptionService:
- startRecording() must check if Relay is active
- If RelayService.shared.isActive → register onAudioChunk callback
- If NOT active → call AudioCaptureService directly
- DO NOT auto-start Relay when recording in main app

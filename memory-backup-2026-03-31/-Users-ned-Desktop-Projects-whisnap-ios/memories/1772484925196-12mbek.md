SYMPTOM: Keyboard extension deep links silently fail with 'Force returning false' in console. The old NSSelectorFromString('openURL:') approach is deprecated.

CAUSE: iOS now force-returns false for UIApplication.openURL(_:). Keyboard extensions can't reference UIApplication directly at compile time.

FIX:
```swift
private func openApp(path: String = "") {
    guard let url = URL(string: "whisnap-ios://\(path)") else { return }
    // KVC bypass — keyboard extensions can't reference UIApplication at compile time
    let selector = NSSelectorFromString("open:options:completionHandler:")
    if let app = UIApplication.value(forKeyPath: "sharedApplication") as? NSObject,
       app.responds(to: selector) {
        app.perform(selector, with: url, with: [:] as NSDictionary)
        return
    }
    showTemporaryError("Open Whisnap to continue")
}
```

PREVENT: Never use NSSelectorFromString('openURL:') in keyboard extensions. The 3-arg 'open:options:completionHandler:' via KVC is the correct modern approach.

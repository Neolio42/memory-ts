QUESTION: What blocks the main thread for ~30 seconds between tapping 'Sign In' in SettingsView and the iOS system ASWebAuthenticationSession banner appearing?

CONTEXT: User reports consistent 30s delay. This is client-side, not server load time. The system dialog is presented by ASWebAuthenticationSession which requires main thread availability.

BLOCKERS: Investigation started but not completed. Last read files: AuthService.swift, SettingsView.swift, RecordingView.swift, SettingsViewModel.swift.

3. SettingsVerificationService doing synchronous I/O on startup
4. ASWebAuth presentation itself being delayed by NavigationStack presentation queue
5. Task priority — sign-in Task competing with other background work

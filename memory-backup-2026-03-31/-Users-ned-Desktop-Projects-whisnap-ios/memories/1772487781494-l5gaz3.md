FACT: iOS keyboard extensions share microphone permission with their containing app. The extension does NOT have a separate permission entry in Settings. There is no way to trigger the system permission dialog from within the keyboard extension.
CONTEXT: If the user has never opened the containing app and granted mic access, the keyboard extension's AVAudioSession will fail with permission denied — but the failure looks like an audio engine error, not a permission error.
APPLICATION: In keyboard extensions: (1) Check AVAudioSession.sharedInstance().recordPermission before starting audio. (2) If .undetermined or .denied, show message telling user to open the main app. (3) The containing app (or any AVCaptureSession usage in the main app) is what triggers the iOS permission dialog.

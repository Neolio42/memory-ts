DEBUG
SYMPTOM: Recording starts (mic active, WebSocket packets sending) but UI stuck on 'Initializing' permanently. Stop button unreachable.
CAUSE: RecordingView uses @State private var viewModel: TranscriptionViewModel? (line 158). @State with ObservableObject does NOT auto-observe @Published changes. When viewModel.isLoading goes false and status goes to .recording, SwiftUI never re-renders because no @State property changed.
FIX: Add @State private var _vmTick = false. Add .onReceive(viewModel?.objectWillChange ?? PassthroughSubject<Void,Never>().eraseToAnyPublisher()) { _ in _vmTick.toggle() }. Reference let _ = _vmTick inside ZStack body so SwiftUI tracks it as dependency.
WRONG APPROACH: for await _ in vm.objectWillChange.values crashes with 'Received an output without requesting demand' — Publisher+AsyncSequence bridge has a known demand bug. Use .onReceive instead.
PREVENT: Use @StateObject for ObservableObjects in SwiftUI. If @State is required (e.g. optional viewmodel), bridge objectWillChange via .onReceive, never via .values async sequence.

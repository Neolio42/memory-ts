DECISION
DECISION: Set lastReadChunkIndex=0 when keyboard starts recording — backfill ALL existing chunks
OPTIONS:
- lastReadChunkIndex=currentCount: skip existing audio, only stream new chunks going forward
- lastReadChunkIndex=0: backfill from beginning of relay session, then continue streaming
REASONING: User starts relay in main app FIRST (which captures audio immediately), then opens keyboard. The keyboard should capture all audio the relay already captured — 'app starts immediately just backfills audio' (user clarification). Setting to currentCount silently drops all pre-keyboard audio.
REVISIT WHEN: If relay sessions are very long (>10 minutes), backfilling from 0 could send huge amounts of data. May need sliding window.

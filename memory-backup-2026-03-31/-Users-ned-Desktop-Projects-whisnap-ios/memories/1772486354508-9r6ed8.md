PATTERN: Strict lifecycle ordering to prevent watchdog kills in keyboard extensions
WHEN: Always — any heavy work in viewWillAppear or viewDidLoad risks watchdog kill

CORRECT SEQUENCE:
```
viewDidLoad:
  - Add keyboardView (lazy var, built once)
  - Constraints only
  - NO network, NO keychain, NO UserDefaults, NO timers

viewWillAppear:
  - applyKeyboardHeight() ← must be here to prevent height-jump on switch
  - refreshVoiceStrip() ← lightweight state check only

viewDidAppear:
  - DispatchQueue.main.asyncAfter(0.3) { needsInputModeSwitchKey check }
  - DispatchQueue.main.asyncAfter(1.5) { startRelayPolling(); checkPendingTranscription() }
  - DispatchQueue.main.asyncAfter(3.0) { checkFullAccess() }

viewWillDisappear:
  - stopRelayPolling()
  - transcriptionService?.cancel()
  - NO view destruction, NO nil assignments to keyboardView
```

WHY: iOS keyboard extensions get ~50MB RAM limit + watchdog timeout. Spurious XPC launches fire viewDidLoad but not viewWillAppear — any heavy work in viewDidLoad is wasted and spikes memory. The 1.5s delay ensures host XPC connection is established before network/keychain access.

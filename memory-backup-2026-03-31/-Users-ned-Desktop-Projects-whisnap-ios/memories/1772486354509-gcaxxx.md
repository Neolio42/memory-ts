WHAT: System-matching keyboard layout constants for WhisnapKeyboard
WHERE: WhisnapKeyboard/KeyboardView.swift

KEY CONSTANTS:
```swift
private let toolbarHeight: CGFloat = 36  // system QuickType bar is 36-38pt, NOT 44
private let rowSpacing: CGFloat = 6
private let keySpacing: CGFloat = 6
// NO sideInset, NO bottomInset — edge-to-edge with zero insets
```

PROPORTIONAL KEY WIDTHS (instead of fixed points):
```swift
// Row 3: shift and delete
shift.widthAnchor.constraint(equalTo: row.widthAnchor, multiplier: 0.13)
del.widthAnchor.constraint(equalTo: row.widthAnchor, multiplier: 0.13)

// Bottom row
globe.widthAnchor.constraint(equalTo: row.widthAnchor, multiplier: 0.10)
ret.widthAnchor.constraint(equalTo: row.widthAnchor, multiplier: 0.22)
// numbers key: 0.115, space fills remaining
```

KEYS CONTAINER — zero insets, top pinned directly to toolbarHeight:
```swift
NSLayoutConstraint.activate([
    container.topAnchor.constraint(equalTo: topAnchor, constant: toolbarHeight),
    container.leadingAnchor.constraint(equalTo: leadingAnchor),    // NO sideInset
    container.trailingAnchor.constraint(equalTo: trailingAnchor),  // NO sideInset
    container.bottomAnchor.constraint(equalTo: bottomAnchor),      // NO bottomInset
])
```

WHY: Fixed pixel widths break on SE (small) and landscape. Proportional widths scale automatically. toolbarHeight=44 made the voice strip too tall vs system suggestion bar.

SYMPTOM: Keyboard appears then immediately switches back to another keyboard. Multiple viewDidLoad calls with XPC handshake warnings.
CAUSE: iOS keyboard extensions are killed when they exceed ~50MB RAM. Destroying and rebuilding keyboardView on every show/hide cycle (removing from superview + nil) causes allocation spikes — 30+ buttons, constraints, shadow layers all reallocated.
FIX:
```swift
private lazy var keyboardView: KeyboardView = {
    let kb = KeyboardView()
    kb.delegate = self
    kb.translatesAutoresizingMaskIntoConstraints = false
    return kb
}()

override func viewDidLoad() {
    super.viewDidLoad()
    // Build ONCE, never destroy
    view.addSubview(keyboardView)
    NSLayoutConstraint.activate([...])
}

override func viewWillDisappear(_ animated: Bool) {
    super.viewWillDisappear(animated)
    // Only pause services — DO NOT removeFromSuperview or nil the view
    stopRelayPolling()
    transcriptionService?.cancel()
}
```
PREVENT: Never call keyboardView?.removeFromSuperview() + keyboardView = nil in viewWillDisappear. View stays in memory across keyboard show/hide cycles.

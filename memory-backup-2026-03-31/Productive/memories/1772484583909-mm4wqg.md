PATTERN: OpenClaw has three completely separate layers that people keep mixing up

SOUL.md = Identity/personality. Who the agent IS. How it talks, what it optimizes for, behavior rules. This is where tone, accountability partner role, and research capabilities live. Evolves over time.

HEARTBEAT.md = A simple periodic prompt injected every N minutes. The text gets sent verbatim as user message. Agent checks HEARTBEAT.md, does the check, replies HEARTBEAT_OK if nothing to report (suppressed). Should be SHORT and GENERIC - just: check time, read today/yesterday memory, check active todos, act or shut up. NOT where you hardcode specific scenarios, projects, or reminders.

Cron jobs = Scheduled tasks. Morning/evening check-ins, specific time-triggered messages. The right place for 'remind me every Friday at 5pm.'

WHY: Three separate jobs. HEARTBEAT got broken when Atlas put project-specific stuff (Sunday launch checks etc.) directly into it instead of keeping it generic. Solution: created HOW-YOU-WORK.md to give the agent its own architecture manual.

GOTCHA: If HEARTBEAT.md is empty/blank headers, OpenClaw skips the heartbeat run entirely to save API calls.

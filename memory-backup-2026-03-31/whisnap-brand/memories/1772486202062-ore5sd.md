DEBUG
SYMPTOM: Puppeteer screenshot-based video capture compresses a 16s animation into ~5s — end screen appears at 5s instead of 13s. CSS animations (waveform pulse, cursor blink) also look choppy/wrong.

CAUSE: The capture loop sleeps 50ms between frames for pacing, but the browser JS engine runs setTimeout/setInterval on real wall-clock time. So timers fire much faster than the frame rate implies. CSS animations run on the browser's own clock, not tied to JS at all.

FIX: Use Chrome DevTools Protocol (CDP) virtual time AFTER the page has fully loaded:
1. Load page normally (goto + waitForNetworkIdle)
2. Enable CDP virtual time: `client.send('Emulation.setVirtualTimePolicy', { policy: 'pauseIfNetworkFetchesPending', budget: ... })`
3. Advance virtual time per frame: call CDP to tick by frameInterval ms before each screenshot
4. Also call `document.getAnimations().forEach(a => a.currentTime = virtualMs)` to sync CSS animations

PREVENT: Any time you need frame-accurate video from a browser animation — don't trust real-time sleeps. Always use CDP virtual time for deterministic capture.

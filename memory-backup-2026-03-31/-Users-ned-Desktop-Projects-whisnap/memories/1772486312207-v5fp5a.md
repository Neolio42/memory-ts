WHAT: stop_recording() previously delegated unconditionally to toggle_live_transcription(). Since toggle starts recording when state is Idle, calling stop_recording when already idle would START a new recording - opposite of intent.

WHERE: src/transcription/service.rs ~line 1163

HOW: Fixed to check recording state before delegating. Only calls toggle if actually in a recording state.

WHY: toggle_live_transcription is bidirectional by design. stop_recording must be unidirectional.

GOTCHA: There is a minor TOCTOU - check state, drop lock, re-acquire in toggle. In practice harmless because FN coordinator serializes FN-related actions and worst case is a brief recording that gets cancelled.

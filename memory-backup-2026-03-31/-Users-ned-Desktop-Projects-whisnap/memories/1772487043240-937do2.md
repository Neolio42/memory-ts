PRINCIPLE: FluidAudio and sherpa both run Parakeet TDT 0.6B but via completely different inference paths
FLUIDAUDIO: CoreML on Apple Silicon, Swift SDK, async FFI, v2/v3 model variants. THE ACTIVE BACKEND.
SHERPA: ONNX runtime on CPU, sherpa_rs crate, ZipFormer transducer. Feature flag 'sherpa' NOT in default features. Dead code.
COMPARISON:
  - Whisper: single .bin file, whisper_rs crate, Metal GPU, SingleFile format
  - Parakeet/FluidAudio: multi-file CoreML, Swift FFI, Manifest format
  - Parakeet/Sherpa: multi-file ONNX, CPU-only, Manifest format (dead)
ROUTING: DynamicTranscriber checks model backend type at runtime, dispatches to WhisperTranscriber or FluidAudioTranscriber
CLEANUP NEEDED: Remove sherpa feature entirely (touches Cargo.toml, inference manager, model registry, transcriber components)

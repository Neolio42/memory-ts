SYMPTOM: The warning 'A hotkey shortcut couldn't register' appears with no actionable detail. The 'Change Shortcut' button in the banner does nothing if user is already on the keyboard settings page.

CAUSE:
- `classifyIssues()` in HotkeyStatusBanner.tsx lumps all hotkey failures into one generic message. The backend has specific strings like 'Recording hotkey failed to register' and 'Toggle recording hotkey failed to register' (service.rs:1513, 1582) but they're not surfaced distinctly.
- Banner button calls `setPageMode('settings')` and `setActiveSettingsSection('Keyboard')` — no-op if already there.

FIX NEEDED:
- Surface specific failure messages per keybind instead of generic fallback
- Make 'Change Shortcut' button scroll to / highlight the specific failing keybind input

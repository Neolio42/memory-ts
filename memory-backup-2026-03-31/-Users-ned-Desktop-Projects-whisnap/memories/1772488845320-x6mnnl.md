INSIGHT: CoreML ONNX Runtime EP is confirmed slower than CPU for transducer (encoder/decoder/joiner) models on all M-series chips. Confirmed in sherpa-onnx GitHub issue Dec 2025 (#2910) and independently by parakeet-rs author on M4 MacBook Pro.

BEFORE: Assumed CoreML would accelerate ONNX transducer inference on Apple Silicon.

AFTER: CoreML EP compiles static subgraphs poorly when models have dynamic shapes and stateful loops — exactly what TDT transducers use. RTF barely improved with CoreML vs CPU.

IMPLICATIONS:
- Remove CoreML provider detection/enabling from sherpa-rs backend
- The real performance lever is ADAPTIVE THREAD COUNT (scales well with CPU cores)
- Use std::thread::available_parallelism() instead of hardcoded 8 threads
- MLX is the only path to real GPU/ANE acceleration but has no Rust bindings (Python/Swift only)
- This applies to ALL ONNX-based approaches: sherpa-rs, parakeet-rs (altunenes), ort direct — all hit same ceiling

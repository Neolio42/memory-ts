SYMPTOM: First FN key press after selecting FluidAudio model appears frozen (30-60s delay)
CAUSE: Pre-warm was skipping FluidAudio models, so load_model() called on first transcribe instead

FIX in src-tauri/src/features/inference/manager.rs preload_current_model():
```rust
#[cfg(feature = "fluidaudio")]
"fluidaudio" => {
    let model_id_owned = model_id.to_string();
    let version = fluidaudio::version_from_model_id(&model_id_owned);
    tokio::spawn(async move {
        match fluidaudio::load_model(&version).await {
            Ok(()) => info!("FluidAudio model pre-warmed"),
            Err(e) => warn!("FluidAudio pre-warm failed: {}", e),
        }
    });
}
```

WHY: AsrModels.downloadAndLoad() + CoreML compilation takes significant time on first call. Pre-warming ensures the actor singleton is initialized before the user presses FN.

GOTCHA: The download_manager.register_download() in service.rs handles the user-initiated download flow separately. Pre-warm is fire-and-forget (no progress UI needed).

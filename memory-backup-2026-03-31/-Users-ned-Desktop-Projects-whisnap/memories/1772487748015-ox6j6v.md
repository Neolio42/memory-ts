WHAT: FluidInference/parakeet-tdt-0.6b-v3-coreml model on HuggingFace contains ~10 .mlmodelc directories (Encoder.mlmodelc, MelSpectrogram.mlmodelc, Joiner.mlmodelc, etc.), each with nested weights/weight.bin files inside.

WHERE: src-tauri/src/features/model_management/download_service.rs (~line 485)

CURRENT BEHAVIOR: download_file does model_dir.join(&file.filename) — if filename is 'Encoder.mlmodelc/weights/weight.bin', the path is created correctly BUT the parent directory 'Encoder.mlmodelc/weights/' may not exist → file write fails.

FIX NEEDED: Before writing each downloaded file, add:
  if let Some(parent) = dest_path.parent() {
      tokio::fs::create_dir_all(parent).await?;
  }

MANIFEST APPROACH: Pre-enumerate all files via HuggingFace API (GET /api/models/{repo}/tree/main?recursive=true), generate manifest entries with full relative paths as filename. Each file downloads to correct nested location.

GOTCHA: .mlmodelc directories contain compiled CoreML — they're directories, not files. Only the LEAF files inside them need downloading. The directories themselves are created implicitly via create_dir_all.

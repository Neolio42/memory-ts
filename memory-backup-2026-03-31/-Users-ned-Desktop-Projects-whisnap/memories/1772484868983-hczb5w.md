WHAT: The FN keybind coordinator in service.rs was hardcoded to assume bare FN = PTT and FN+key = toggle. Refactored so each handler reads all three keybind settings (PTT, toggle, command) and routes to the correct action dynamically.

WHERE: src-tauri/src/features/hotkeys/service.rs

HOW:
- handle_fn_key_event: checks which actions map to "FN" to decide whether to enter FnHeld
- handle_shortcut_event: checks PTT/toggle/command keybinds to route FN+key events
- check_fn_hold_action: reads was_toggle_active from FnHeld state to start vs stop toggle
- New ToggleRecordingActive state: bare-FN toggle recording persists after FN release
- New was_toggle_active: bool field on FnHeld so second ≥300ms hold stops toggle

WHY: Making keybinds fully swappable (e.g. PTT = FN+Space, toggle = bare FN) required the coordinator to not assume which action is which.

GOTCHA: The ≥300ms delay (language switch protection) only applies to bare FN — FN+key combos fire instantly on key-down because macOS already distinguishes them from language switches.

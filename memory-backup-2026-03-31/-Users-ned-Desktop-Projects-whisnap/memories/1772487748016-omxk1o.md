INSIGHT: The standard ONNX Runtime CoreML Execution Provider (EP) cannot accelerate transducer/TDT models on Apple Silicon. This affects ALL ONNX-based approaches: sherpa-rs, sherpa-onnx, ort, parakeet-rs.

BEFORE: Assumed CoreML EP would give ANE acceleration like it does for encoder-only models (whisper, wav2vec)

AFTER: TDT (Token and Duration Transducer) uses an autoregressive decode loop: encoder runs once, but the joiner/predictor network runs iteratively per token. CoreML cannot express this stateful loop as a computation graph — it can only accelerate feed-forward passes.

FLUIDAUDIO'S SOLUTION: Run encoder and mel spectrogram as CoreML models (where they get ANE acceleration), implement the TDT token prediction loop in native Swift code. This hybrid approach gives ~110x RTF.

IMPLICATIONS:
- sherpa-onnx issue #2910 confirms this is fundamental, not a fixable bug
- Any future transducer model (RNN-T, TDT, etc.) will have the same issue with ONNX CoreML EP
- The right pattern for CoreML + transducers: native CoreML encoder + native loop implementation
- This is why parakeet-rs CoreML was 'explicitly broken'

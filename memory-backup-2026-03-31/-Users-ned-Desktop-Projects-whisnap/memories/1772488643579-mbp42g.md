PATTERN: All shipped Whisnap apps (v1.0.5 and below) hit staging.api.whisnap.com for update checks because of the CI bug. The workaround is that staging mirrors prod's latest release.

CURRENT STATE (as of 2026-03-02):
  - Prod API (api.whisnap.com): serves v1.0.5
  - Staging API (staging.api.whisnap.com): also serves v1.0.5 (same binary, same S3 object)
  - All shipped apps update correctly via staging endpoint

TRANSITION PLAN:
  1. Tag and release v1.0.6 (CI now has the sed fix)
  2. Promote v1.0.6 to staging - existing users update to 1.0.6
  3. After updating to 1.0.6, users' apps now check api.whisnap.com (prod) directly
  4. Staging endpoint becomes less critical for update delivery

WHEN: When promoting a new release to staging, ensure it matches or exceeds what prod serves to avoid update confusion.

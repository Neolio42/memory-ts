SYMPTOM: Swapping push-to-talk (bare FN) and toggle recording (FN+Space) causes both keybinds to stop working entirely.

CAUSE: The Rust FN coordinator has two separate handlers that are hardwired:
- `handle_fn_key_event`: only checks push-to-talk keybind setting, only works if it equals bare 'FN'. If push-to-talk is 'FN+Space', this function returns None — FN key press is dead.
- `handle_shortcut_event`: only checks toggle and command mode keybinds, never reads push-to-talk. If toggle is set to bare 'FN', `parse_fn_keybind('FN')` returns None — FN+Space is also dead.

Both handlers are hardcoded by action type, not driven by what the keybind setting actually says.

FIX NEEDED: Both handlers must check ALL keybinds and route to whichever action matches the incoming key event. The coordinator needs to be keybind-aware, not action-hardcoded.

PREVENT: Never assume a UI setting is 'configurable' without verifying the backend actually reads the setting dynamically in all code paths.

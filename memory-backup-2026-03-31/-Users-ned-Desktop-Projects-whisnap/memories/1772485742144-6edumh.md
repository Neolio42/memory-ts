DEBUG: CF String Double-Free in ax_read_string

SYMPTOM: `CFString::wrap_under_get_rule` + explicit `CFRelease` = double-free on every successful AX string read. `wrap_under_get_rule` retains on drop AND we were calling CFRelease manually.

CAUSE: `wrap_under_get_rule` does NOT take ownership of a +1 ref — it borrows and adds its own retain. When we then called `CFRelease` explicitly, we released twice.

FIX:
```rust
// WRONG:
let cf_string = CFString::wrap_under_get_rule(value as *const _);
CFRelease(value); // double-free!

// CORRECT:
let cf_string = CFString::wrap_under_create_rule(value as *const _);
// No manual CFRelease — wrap_under_create_rule takes ownership of the +1 ref
```

PREVENT: `wrap_under_create_rule` = you own a +1 ref (from Copy rule outputs like AXUIElementCopyAttributeValue). `wrap_under_get_rule` = borrowed, adds its own retain. Always match the CF ownership convention to the CF function naming (Copy = create rule, Get = get rule).

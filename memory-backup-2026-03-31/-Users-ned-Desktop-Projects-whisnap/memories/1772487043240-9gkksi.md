WHY: SDK v0.12.1 added AsrModels.load(from:configuration:version:) for offline/manual loading from local directory. This replaces downloadAndLoad() which had no progress/cancel support.
GOTCHA: Open question remains — AsrModels.load(from:) documentation says it expects 'the staged HuggingFace repo folder itself'. If it requires pre-compiled models from SDK cache (not raw HuggingFace files), fallback plan is: trigger downloadAndLoad() once on first use, then subsequent loads use load(from:) pointing at SDK cache directory.
RUST SIDE: fluidaudio_ffi.rs extern C declaration has model_dir: *const c_char param. fluidaudio.rs load_model takes (model_id, model_dir). fluidaudio_transcriber.rs resolves model_dir via ModelStorage::get_model_path() before calling load.

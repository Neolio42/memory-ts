SYMPTOM: Downloads showed no progress, no completion, and cancel returned 'No active download found' (because task had already silently failed)
CAUSE: In service.rs, tokio::spawn wrapping the download task returned Ok(()) immediately after registering. Any errors in the spawned task were silently swallowed — nobody awaited the JoinHandle result. Frontend relied purely on progress percent hitting 100% to set done=true.
FIX: Added proper event emission in the spawned download task closure:
  - On success: app_handle.emit('model_download_completed', model_id)
  - On error: app_handle.emit('model_download_error', {model_id, error: err.to_string()}) + download_manager.remove_download()
WHERE: src-tauri/src/features/model_management/service.rs — the tokio::spawn block in download_model()
NOTE: This fix applies to BOTH Manifest (FluidAudio/Parakeet) AND SingleFile (Whisper) downloads since both go through the same spawned task. Frontend's onModelDownloadComplete sets percent:100, done:true definitively.

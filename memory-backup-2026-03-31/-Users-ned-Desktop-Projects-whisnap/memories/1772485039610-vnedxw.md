SYMPTOM: User cannot swap push-to-talk and toggle keybinds because duplicate detection blocks both directions.

CAUSE: KeybindInput.tsx lines 170-172 and 273-275 — both the FN capture path and regular hotkey path reject any keybind already assigned to another action. With no 'Clear' option:
- Setting push-to-talk to 'FN+Space' blocked because toggle owns it
- Setting toggle to 'FN' blocked because push-to-talk owns it
- No way to temporarily unset either one

FIX OPTIONS:
1. Add a 'Clear' button to unset a keybind temporarily (allows manual two-step swap)
2. Smart duplicate swap: if new value conflicts, automatically reassign the conflicting keybind to the displaced value
3. Pending/atomic commit: allow staging both changes before validating

USER WORKAROUND: Set both to intermediary unused keybind first, then assign target values.

PATTERN: User pushed back on 'I don't believe it' when only unit tests shown. User's standard for 'done' = real DB round-trips + real LLM calls showing measurably different behavior.
WHEN: Any feature that involves DB persistence, LLM prompting, or learning behavior
WHY: Unit tests with mocked Prisma prove logic in isolation but don't prove the system actually works end-to-end
APPLICATION:
- Always write an integration test against real dev DB (user: 'Theres already a prisma that npm run dev connects to')
- For LLM features: prove output is measurably different (email vs Slack output lengths/structure)
- Format test results as concrete numbers: '232 chars with greeting/signoff' vs '112 chars single line'
- Run API keys test even locally — they exist in root .env.local

INSIGHT: TranscriptionHistory already stores both `transcript` (raw ASR) and `llmOutput` (LLM enhanced). This is the diff source. No new data needed.

ALGORITHM:
1. On each transcription completion, extract word-level diffs between `transcript` and `llmOutput`
2. Identify LLM corrections: words where ASR wrote X and LLM wrote Y
3. Apply strict filter — only keep candidates that are:
   - Capitalized proper nouns (names, product names, place names)
   - Technical terms (camelCase, hyphenated, acronyms all-caps)
   - NOT common English word corrections ('their' → 'there', 'its' → 'it's')
   - NOT grammar corrections, punctuation, or structural changes
4. Track frequency: candidate must appear corrected 2+ times before being promoted to vocab list
5. Once promoted: inject into ASR initial_prompt so it's correct at speech-to-text level, not just LLM level

WHAT THIS CATCHES: 'Whisnap', 'kubectl', 'Nedas', 'Kubernetes', 'Prisma', custom product names, coworker names
WHAT THIS REJECTS: grammar fixes, common word substitutions, spelling corrections of regular words

FIRE-AND-FORGET: Run as event-triggered background job after response is sent. Never blocks user.

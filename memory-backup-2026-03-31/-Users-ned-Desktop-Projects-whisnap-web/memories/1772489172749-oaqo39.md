INSIGHT: A 401 error appearing in client logs with no corresponding entry in server access logs means the request either (a) never left the client, (b) was rejected by infrastructure before reaching the app (load balancer, ingress), or (c) the HTTP client generated the error locally from a pre-flight check.

BEFORE: Assumption was the 401 came from the Express API auth middleware — investigated DB connection pooling, read replica lag, Redis cache misses as root causes.

AFTER: Server log audit showed zero matching requests. The gap between client-reported 401 and server logs is the critical signal — don't assume client error codes originate from the server.

IMPLICATIONS:
1. Always correlate client error timestamps with server access logs before investigating server-side code
2. For Rust/native HTTP clients, check for auth interceptors that can short-circuit requests
3. 'Device lookup succeeds (cached locally)' in client log = that request never hit the server either
4. Response times under ~100ms for remote calls can indicate local generation

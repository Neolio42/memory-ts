SYMPTOM: Admin dashboard shows phantom fields as 'not set', while real data lives in 'Additional fields' section that can't be edited. Staging DB has duplicate entries for every field.

CAUSE: Desktop app sends camelCase field paths (ui.themeMode, model.modelId, transcription.autoPaste, audioProcessing.audioQualityPreset etc.) while shared/types/sync.ts schema defines snake_case paths. Zod .passthrough() stores both versions silently. LWW resolves conflicts per exact field path, so themeMode and theme_mode are treated as completely separate fields.

FIX: Strict allowlist on server - only accept snake_case canonical field paths. Unknown fields get 400 error (not silent storage). DB migration to clean up all camelCase and junk fields.

PREVENT: Never use .passthrough() on sync schema. Server must enforce the schema, not just define it.

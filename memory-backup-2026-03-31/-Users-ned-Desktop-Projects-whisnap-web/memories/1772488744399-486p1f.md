SYMPTOM: model_id null sent by client to clear model selection was being converted to undefined in parseSettings(), then re-sent as undefined — clearing operation appeared to work but DB still held old value
CAUSE: Zod schema was .nullish() (string | null | undefined) but TypeScript type was string | undefined. Also parseSettings() used `raw.model?.model_id || undefined` which converts null to undefined.
FIX: 
  1. shared/types/sync.ts: model_id?: string | null
  2. settingsCache.ts parseSettings(): model_id: raw.model?.model_id !== undefined ? raw.model.model_id : undefined
PREVENT: When a field intentionally accepts null as a 'clear' sentinel, use explicit !== undefined check instead of || undefined in parseSettings()

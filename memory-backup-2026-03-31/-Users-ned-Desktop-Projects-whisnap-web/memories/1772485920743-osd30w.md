MECHANISM:
1. Track transcription count per (userId, bundleId) on TranscriptionHistory
2. After every 10 transcriptions for a given pair, trigger background job (NOT in hot path)
3. Job pulls last 20 final LLM outputs for that (userId, bundleId)
4. Sends to cheap model (Haiku/Flash-Lite) with meta-prompt:
   'Here are 20 texts this user produced for [app]. Describe their writing style in 3-4 sentences. Cover: formality level, average sentence length, greeting/sign-off patterns, tone, distinctive patterns.'
5. Store result as styleFingerprint on DestinationProfile
6. On next transcription for that app: inject fingerprint into system prompt as style guidance
7. Re-runs every 10 new transcriptions — style evolves as usage grows

THE EXPANDING SYSTEM TIMELINE:
- Day 1: Generic output, sounds like AI
- Transcription 10: Vocabulary mostly right
- Transcription 30: Format per app dialed in
- Transcription 100: Voice captured, output sounds like user
- Transcription 500: Indistinguishable from user's own writing

WHY NO EDIT TRACKING NEEDED: User auto-pastes, we never see edits. The learning happens purely from output patterns, not corrections. This is by design — simpler and still effective.

COST: Cheap background model, ~200 token output, not in hot path. Negligible.

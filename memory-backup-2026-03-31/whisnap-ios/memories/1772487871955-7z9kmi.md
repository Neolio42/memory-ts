SYMPTOM: AVAudioEngine.start() in UIInputViewController always fails with 'AURemoteIO.cpp AUIOClient_StartIO failed (2003329396)' — error code 0x77686174 = FourCC 'what'
CAUSE: Apple platform sandbox blocks ALL audio input APIs in keyboard extensions regardless of Full Access (RequestsOpenAccess=true), mic permission granted, or audio session configuration tried. Apple QA1872 explicitly documents this. Custom keyboard docs state 'Custom keyboards have no access to the device microphone.'
FIX: Architecture shift — main app must do all audio capture; keyboard reads from shared storage or receives text results
PREVENT: Never attempt AVAudioEngine, AudioQueue, AVAudioRecorder, or any Remote I/O start in a keyboard extension. 'Full Access' adds network/pasteboard/shared-container access, NOT mic access.
NOTE: Wispr Flow pattern — open main app, start audio there, write results to App Group, keyboard reads and inserts text

INSIGHT: When SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor is set as a build setting, ALL classes/structs are implicitly @MainActor unless opted out. NSLock on these types blocks the main thread unnecessarily since all access is already serialized by actor isolation.

BEFORE: MonitoringService had `private var metricsLock = NSLock()` with lock/unlock calls throughout
AFTER: All NSLock calls removed — actor isolation already serializes access

WHERE: MonitoringService.swift, NetworkQualityMonitor.swift (NetworkQualityMonitor kept its lock because it has a custom NWPathMonitor dispatch queue and is NOT @MainActor)

GOTCHA: NSLock is still valid for non-MainActor classes that have background thread access (e.g., audio callback threads). Check whether the class is genuinely @MainActor before removing locks.

PATTERN: Swift's `static let` with closure is guaranteed thread-safe by the runtime (dispatch_once semantics). No NSLock needed.

FIXED ISSUES:
1. NSLock singleton with async Task after lock release → race: instance returned before settings loaded
   FIX: `static let shared: SettingsStore = { let i = SettingsStore(settings: Settings.default); Task { @MainActor in i.settings = await i.persistenceActor.load() }; return i }()`

2. Duplicate reload() — async version and sync version with completely different behavior (sync flashed defaults)
   FIX: Removed sync version, kept only `func reload() async`

3. `await shared.settings = Settings.default` — INVALID Swift syntax (can't await a property setter)
   FIX: `Task { @MainActor in shared.settings = Settings.default }`

4. Save debounce calling `self?.save()` which creates ANOTHER Task
   FIX: Call `await self.persistenceActor.save(self.settings)` directly

5. `nonisolated(unsafe)` on immutable string constants — misleading
   FIX: Removed, just `static let suiteName = ...`

WHERE: Settings.swift — SettingsStore class, SettingsPersistenceActor

PATTERN: Relay shared audio stream architecture
COMPONENTS:
- RelayService.swift (main app): wraps AudioCaptureService, writes 16kHz mono Int16 PCM 4096-sample chunks to App Group shared directory, tracks session with timeout
- RelayView.swift (main app): 'Relay active — switch back to your app' UI shown when keyboard triggers relay start
- KeyboardTranscriptionService.swift (extension): reads PCM files from shared dir, streams to WebSocket wss://api.whisnap.com/ws, delivers transcript
- KeyboardViewController.swift: checks if Relay is active (flag in shared UserDefaults) before recording; if not active, opens app via extensionContext?.open(URL(string: 'whisnap-ios://relay'))
- Settings: relayDuration (default 5 min), relay enable/disable toggle
WHY: iOS blocks all audio input in keyboard extensions (sandbox restriction). Main app has audio background mode, writes chunks to App Group for keyboard to read.
REJECTED: keyboard records its own audio (impossible), background recording in app controlled by keyboard (too complex, wrong model), triggeredFromKeyboard binding in RecordingView (temporary workaround, reverted)
Audio format: 16kHz, mono, Int16 PCM, 4096 buffer = ~8KB/chunk, ~4 chunks/sec
URL scheme: whisnap-ios://relay (separate from OAuth)
App Group: group.com.whisnap.app
Shared UserDefaults keys: 'relayActive', 'relayExpiresAt', 'pendingKeyboardTranscript'

DECISION: RecordingView and HistoryView use `@State private var viewModel: TranscriptionViewModel?` and similar — technically wrong (@StateObject required for ObservableObject), but deferred.

REASONING: In practice, every @Published change in the VM causes collateral @State changes (recording state, etc.) that trigger SwiftUI re-render anyway. Fixing requires extracting into inner views with @ObservedObject since modelContext from @Environment can't be accessed in a struct's stored property initializer.

REVISIT WHEN: There's a bug where UI doesn't update when ONLY a ViewModel @Published property changes with no collateral @State change. This would confirm the fix is necessary.

RISK: If someone removes the collateral @State changes, VM @Published updates will silently stop driving UI without obvious error.

INSIGHT: iOS keyboard extensions cannot use AVAudioEngine (AUIOClient_StartIO fails). Solution: main app captures audio and writes PCM chunks to App Group shared directory, keyboard reads and streams them.

ARCHITECTURE:
- AudioCaptureService → RelayService → onAudioChunk → CloudTranscriptionService (in-process)
- RelayService → writes chunk_NNNNNN.pcm to <AppGroup>/relay_audio/ (cross-process)
- KeyboardTranscriptionService → reads .pcm files → WebSocket (keyboard side)

FILES:
- RelayService.swift: App/Services/RelayService.swift (~250 lines, @MainActor singleton)
- RelayView.swift: App/Views/RelayView.swift (shown via whisnap-ios://relay URL)
- RecordingOverlayView.swift: WhisnapKeyboard/ (~240 lines, UIKit waveform overlay)

KEY CONSTANTS (RelayKeys enum):
- relayActive (Bool in shared UserDefaults)
- relayExpiry (Date in shared UserDefaults)
- relayChunkCount (Int in shared UserDefaults)

CHUNK FORMAT: raw Int16 LE bytes, ~8KB each (4096 samples at 16kHz), ~4 chunks/sec
FILE PATH: FileManager.containerURL(forSecurityApplicationGroupIdentifier:)/relay_audio/chunk_000001.pcm

IMPORTANT: UIBackgroundModes: audio in Info.plist keeps audio capture alive when user switches to keyboard

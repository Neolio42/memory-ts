QUESTION: How to push settings to cloud when server requires a pre-registered device ID?
CONTEXT: POST /sync/settings returns 400 INVALID_DEVICE_ID when using UIDevice.current.identifierForVendor?.uuidString. Server validates device IDs against registered devices — iOS app has no device registration flow.
BLOCKERS: No device registration API endpoint wired up in the app. Server: 'Device not found or does not belong to you.'
CURRENT STATE: pushSettingsToCloud() is implemented but skipped with TODO comment. syncSettingsFromCloud() (pull) works correctly.
OPTIONS: 1) Implement device registration on first launch (POST to register device, store returned device ID). 2) Find if /desktop/user or auth flow returns a device ID. 3) Remove deviceId requirement from settings endpoint (server change).

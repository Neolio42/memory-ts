QUESTION: Should RelayService chunk writing be made fully thread-safe?
CONTEXT: AudioCaptureService fires onAudioBuffer from audio thread wrapped in @MainActor Task. writeChunk() increments chunkIndex without lock, writes file, then updates UserDefaults — if crash between file write and UserDefaults update, keyboard will never see that chunk. isActive is not checked inside writeChunk.
BLOCKERS: No synchronization primitive on chunkIndex
OPTIONS:
1. Wrap all chunk writing in serial DispatchQueue (audio-safe, ordered)
2. Use atomic Int for chunkIndex
3. Write metadata BEFORE file (keyboard safely retries), not after
PARTIAL FIX APPLIED: Added synchronize() after UserDefaults writes, captured chunkIndex into local variable before use

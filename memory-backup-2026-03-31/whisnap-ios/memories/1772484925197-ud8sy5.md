SYMPTOM: Console spam 'Unable to simultaneously satisfy constraints' with UIInputView.height == 261 vs UIView-Encapsulated-Layout-Height == 874.

CAUSE: The keyboard sets its own height constraint at .required (1000) priority, conflicting with iOS's system encapsulated layout height constraint.

FIX in KeyboardViewController.swift:
```swift
// When setting keyboard height constraint:
let heightConstraint = inputView.heightAnchor.constraint(equalToConstant: keyboardHeight)
heightConstraint.priority = UILayoutPriority(999)  // yield to encapsulated layout
heightConstraint.isActive = true
```

WHY: The system's UIView-Encapsulated-Layout-Height takes precedence when set, but our constraint should guide the preferred height without fighting. Priority 999 lets the system win when it has an explicit height while still providing guidance otherwise.

WHAT: WebSocket handshake protocol between WhisnapKeyboard and wss://staging.api.whisnap.com/ws
HOW - Correct message sequence:
1. Server sends: {type: 'connected'}
2. Client sends: {type: 'auth', token: JWT}
3. Server sends: {type: 'auth_success'} (data nested in 'data' key)
4. Client sends: {type: 'start_transcription', language: 'en', mode: 'keyboard'}
5. Server sends: {type: 'transcription_started', data: {sessionId: '...'}}
6. Client streams: {type: 'audio_data', audioData: <base64>, sessionId: '...'}
7. Client sends: {type: 'finalize', sessionId: '...'}
8. Server sends: {type: 'transcription_complete', data: {text: '...'}} THEN {type: 'session_stopped'}

KEY GOTCHAS:
- Auth type: 'auth' NOT 'authenticate' (was mismatch, caused auth_error)
- Audio data key: 'audioData' NOT 'data'
- sessionId MUST be included in audio_data and finalize — extract from transcription_started response
- Server sends BOTH transcription_complete AND session_stopped — use hasDeliveredFinal flag or text inserts twice
- Server error payload: {success:0, type:'error', error:{code:'...', message:'...'}} — nested in 'error' key
- Server partial/final data: nested in 'data' key: {type:'partial_transcript', data:{text:'...'}}
- Rate limit: 512KB/sec — start lastReadChunkIndex from CURRENT chunk count, not 0

WHERE: WhisnapKeyboard/KeyboardTranscriptionService.swift
WHY: Protocol derived from reverse-engineering main app's WebSocketModels.swift and CloudTranscriptionService.swift

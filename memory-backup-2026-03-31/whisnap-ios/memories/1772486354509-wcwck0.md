WHAT: How 'always-on mic' works between Whisnap main app and keyboard extension
COMPONENTS:
- Main app (RelayService.swift): Captures audio via AVAudioEngine, writes PCM chunks to App Group shared directory, increments chunk count in UserDefaults group.com.whisnap.app
- Keyboard (KeyboardTranscriptionService.swift): On mic tap, reads lastReadChunkIndex = CURRENT count (not 0!), polls every 150ms for new chunks, streams new chunks as base64 audioData to WebSocket
- App Group: group.com.whisnap.app — shared UserDefaults and file directory
- Shared Keychain: $(AppIdentifierPrefix)com.whisnap.shared — JWT token shared between app and keyboard

KEY INSIGHT: keyboard only transcribes from the moment user taps mic:
```swift
// In startRecording() — CRITICAL
let currentCount = UserDefaults(suiteName: appGroupSuite)?.integer(forKey: KeyboardConstants.relayChunkCount) ?? 0
lastReadChunkIndex = currentCount  // NOT 0! Prevents rate limit exceeded
```

WHEN RELAY NOT ACTIVE: keyboard calls openApp(path: "relay") to open main app which starts RelayService
WHEN RELAY ACTIVE: keyboard reads relay chunks and streams to its own WebSocket session
MAIN APP BEHAVIOR: If user presses record IN the main app while relay is active, CloudTranscriptionService hooks into relayService.onAudioChunk instead of starting new audio capture

Rate limit: server enforces 512KB/sec — backfilling from chunk 0 crashes this limit

ARCHITECTURE
PATTERN: iOS keyboard extensions are sandboxed — responder chain terminates at KeyboardViewController, never reaches UIApplication
COMPONENTS:
- Walking responder chain with NSSelectorFromString('openURL:') fails silently
- extensionContext?.open(url:) is unreliable for keyboard extensions
- Best UX: show in-keyboard message 'Open Whisnap app to continue'
WHY: Apple's security model isolates keyboard extensions from app launching
REJECTED: sel_registerName('openURL:') responder chain walk — architecturally cannot work
GOTCHA: No error is thrown when it fails — the app just doesn't open. Must add explicit fallback messaging.

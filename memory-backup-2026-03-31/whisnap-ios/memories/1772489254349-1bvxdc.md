SYMPTOM: UI jank during audio recording or monitoring events. NSLock.lock() blocks whatever thread is calling it — on MainActor, that's the main thread.

CAUSE: MonitoringService (line 35) and AudioCaptureService (lines 20-31) use NSLock for synchronization. With SWIFT_DEFAULT_ACTOR_ISOLATION=MainActor, all access to these classes is already serialized on the main actor — the locks are redundant AND harmful.

FIX: Remove all NSLock instances and lock()/unlock() calls from MonitoringService and AudioCaptureService. Access is already serialized by the MainActor.

If true background-thread access is needed for audio capture (likely), convert the class to an Actor instead of @MainActor, which properly handles concurrent access without blocking.

PREVENT: In a project with SWIFT_DEFAULT_ACTOR_ISOLATION=MainActor, don't use NSLock unless the code explicitly opts out of MainActor with nonisolated or runs on a non-main actor.

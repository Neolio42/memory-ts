SYMPTOM: Build error: 'Call to main actor-isolated instance method in a synchronous nonisolated context' when calling a @MainActor service's method from deinit.
CAUSE: deinit is always nonisolated in Swift concurrency. Even if the class is @MainActor, deinit cannot call @MainActor-isolated methods.
FIX: In deinit, simply nil out the reference (e.g. transcriptionService = nil) instead of calling cancel() or other @MainActor methods. Swift will call deinit on the object which handles its own cleanup. For tasks, store as Task<Void, Never>? and call recordingTask?.cancel() — Task.cancel() is not isolated so it can be called from deinit.
PREVENT: Design services so that deinit cleanup happens via deallocation, not explicit method calls. Or use weak references and let the object clean itself up.

SYMPTOM: Keyboard gets server errors — authentication rejected, audio not processed, no transcripts
CAUSE: 4 protocol mismatches between KeyboardTranscriptionService and server (main app was correct reference):
  1. Auth type: keyboard sent 'authenticate', server expects 'auth'
  2. Audio key: keyboard sent 'data', server expects 'audioData'
  3. Session ID: keyboard omitted sessionId from audio_data and finalize messages
  4. Start message: keyboard sent extra fields (format, sampleRate, channels) not in protocol
FIX: 
  - sendAuthentication(): type = 'auth'
  - sendStartTranscription(): remove format/sampleRate/channels, only send language + mode
  - capture sessionId from server handshake response
  - sendAudio(): include sessionId, use 'audioData' key
  - sendFinalize(): include sessionId
  - disconnect(): clear sessionId
PREVENT: Always diff keyboard WebSocket messages against main app WebSocketClient.swift when protocol changes

DEBUG: Critical callback chain bug that was identified and fixed.

SYMPTOM: Second recording session receives no audio - transcription produces nothing.

CAUSE: setupCallbacks() is called once in init() and sets relayService.onAudioChunk. But stopRecording() sets relayService.onAudioChunk = nil. Subsequent startRecording() calls never re-register the callback.

FIX: In startRecording(), after state setup, explicitly re-register:
```swift
relayService.onAudioChunk = { [weak self] pcmData in
    Task { @MainActor [weak self] in
        await self?.handleAudioBuffer(pcmData)
    }
}
```

CALLBACK CHAIN:
AudioCaptureService.onAudioBuffer → RelayService (writes file + calls onAudioChunk) → CloudTranscriptionService.handleAudioBuffer

stopRecording() behavior: sets onAudioChunk = nil, does NOT call relayService.stopSession() (Relay has its own timer)
reset() behavior: does NOT need to touch Relay (onAudioChunk already nil'd by stopRecording)

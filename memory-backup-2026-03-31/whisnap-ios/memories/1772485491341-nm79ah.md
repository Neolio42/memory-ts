PATTERN: RelayService captures audio via AudioCaptureService → writes PCM chunk files to App Group shared directory (group.com.whisnap.app) → KeyboardTranscriptionService polls directory and streams chunks over WebSocket
COMPONENTS:
- RelayService: owns audio engine, writes chunks, exposes onAudioChunk callback for in-process listeners
- CloudTranscriptionService: hooks into relayService.onAudioChunk when relay active, else uses AudioCaptureService directly
- KeyboardTranscriptionService: reads chunk files, backfills from chunk 0 to get full session audio
WHY: Keyboard extensions can't own AVAudioEngine. Relay pre-captures audio so keyboard can start dictating instantly.
REJECTED: Deep linking to start relay from keyboard — extensionContext?.open() is unreliable from keyboard extensions, replaced with error toast
KEY INSIGHT: Always backfill from chunk index 0, not current count. Relay already captured audio before keyboard started.

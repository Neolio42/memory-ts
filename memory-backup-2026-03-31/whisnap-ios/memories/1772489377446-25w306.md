PATTERN: Magic link auth flow with ASWebAuthenticationSession requires special handling because the user intentionally leaves the browser to check email — this is NOT an error.

WHEN USER CANCELS ASWEBAUTH:
- Standard error handling shows error state
- Magic link: user dismisses browser to go check email
- FIX: Catch ASWebAuthenticationSessionError.canceledLogin and show 'Check your email for a sign-in link' state

WHEN MAGIC LINK SUCCEEDS:
- Universal link opens app → handleMagicLink() exchanges token → AuthService.isAuthenticated = true
- The SignInView sheet is still open (no callback to dismiss it)
- FIX: .onChange(of: authService.isAuthenticated) { if $1 { dismiss() } } in SignInView

SETTINGS VIEW:
- showingSignIn was @State that never got set to true (no sign-in button existed!)
- FIX: Add sign-in section when !authService.isAuthenticated, button sets showingSignIn = true
- FIX: @ObservedObject private var authService = AuthService.shared so section reacts to auth changes

WHERE: RecordingView.swift (SignInView), SettingsView.swift

GOTCHA: SettingsViewModel.isAuthenticated is a computed property from AuthService but SettingsViewModel doesn't forward objectWillChange — use AuthService directly as @ObservedObject.
